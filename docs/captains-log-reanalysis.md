## 2. Official 2d20 Mechanics — How the Game Actually Works

### 2.1 Task Attempts (Core Mechanic)

**Official Rules:**
1. **Target Number** = One Attribute value + one Discipline value (for characters) OR one System value + one Department value (for ships). This is NOT a fixed number — it's derived from the character/ship stats.
2. **Difficulty** = Number of successes needed (set by narrative context, typically 1 for standard tasks).
3. **Roll 2d20** — each die that rolls **equal to or below** the Target Number is a **success**.
4. **Natural 20** on any die = **complication** (generates Threat), NOT a success.
5. **Focus bonus** — if a Focus applies, any die rolling equal to or below the Discipline value counts as **2 successes**.
6. **No Focus** — only a roll of **1** counts as 2 successes.
7. **Successes ≥ Difficulty** = Task succeeded.
8. **Excess successes** = **Momentum** generated.
9. **Zero successes** = Task failed.

**Captain's Log Specific Differences from STA:**
- **Maximum 1 Momentum** can be generated per task roll (vs unlimited in STA).
- **Maximum 2d20** can be rolled — cannot spend Momentum to buy extra dice.
- **Momentum can be spent to reroll one die** (not to add dice).
- **Momentum can be spent to remove a Threat** or gain an advantage.
- **Complications work differently** — tailored for solo play (page 193).

### 2.2 Momentum System

**Official Rules:**
- Momentum is a **banked resource** (max 1 in Captain's Log).
- Can be spent to:
  - Reroll one die on a task attempt.
  - Remove a Threat.
  - Gain an advantage (roll on advantage table).
- Excess successes beyond difficulty generate Momentum (capped at 1).

### 2.3 Threat System

**Official Rules:**
- Threat represents **complications** in the narrative.
- Generated by:
  - Rolling natural 20s (complications).
  - Failed task attempts.
  - Narrative choices.
- Threat can be:
  - Spent by the player to gain a boon (extra die, auto-success).
  - Resolved via complication tables.
  - Removed by spending Momentum.

### 2.4 Combat (Physical Conflict)

**Official Rules:**
- **Simplified** compared to STA.
- Characters and opponents have **hits** (health).
- If no initiative, both start with **1 hit**.
- Each round: perform a task attempt.
  - **Success** = deal 1 hit to opponent.
  - **Failure** = take 1 hit yourself.
  - **Extra success** = gain Momentum (can be spent).
  - **Natural 20** = gain a complication/threat.
- Repeat until one side is defeated.

### 2.5 Starship Combat

**Official Rules:**
- Same as physical combat but on a larger scale.
- Ship's health based on **scale** (Small=2, Medium=3, Large=4, Capital=5, Station=6).
- **Two extra hits** represent critical damage to systems.
- Task attempts use ship stats (System + Department).

### 2.6 Mission Structure

**Official Rules:**
- **Three-act structure** with **15 narrative beats** total (5 per act).
- Each beat: narrate → task attempt (if needed) → resolve → narrate outcome.
- Acts separated by **in-character log entries**.
- Scenes can include: change of scenery, task requiring a roll, narrative development.
- Mission types generated via probability matrixes.

### 2.7 Probability Matrixes (Oracles)

**Official Rules:**
- **Yes/No Probability Matrix** — the core oracle tool.
- Probability levels: Very Unlikely, Unlikely, 50/50, Likely, Very Likely, Certain.
- **Over 100 random tables** for:
  - Mission types, themes, advantages, complications.
  - Encounters, NPCs, locations, alien civilizations.
  - Maintenance downtime, career events.
  - Alien worlds, polities, allies, enemies.

### 2.8 Character Creation (Lifepath)

**Official Rules:**
- **Lifepath generation** — narrative choices that build the character step by step.
- Supports **any type of character**, not just Starfleet captains.
- Choices determine: background traits, attributes, disciplines, focuses, talents, values.
- **Creation in play** method also available for faster start.
- Attributes: Fitness, Presence, Strength, Reason, Technical, Insight (6 attributes).
- Disciplines: Command, Engineering, Leadership, Medicine, Operations, Science, Security (7 disciplines in some editions, 6 in others).

### 2.9 Starship Creation

**Official Rules:**
- Starships have **systems** (Comms, Computers, Engines, Sensors, Structure, Weapons).
- Starships have **departments** (Command, Engineering, Medical, Operations, Science, Security).
- Starships have **attributes** (same 6 as characters).
- **Talents** provide special abilities.
- **Scale** determines hit points in combat.
- Stations follow similar rules.

## 3. Current Implementation vs Official Rules — Gap Analysis

### 3.1 🔴 Critical: Dice Mechanics Are Fundamentally Wrong

**File:** `DiceService.java`

| Aspect | Official Rules | Current Implementation | Status |
|--------|---------------|----------------------|--------|
| Target Number | Attribute + Discipline (variable) | Fixed default 11 | ❌ Wrong |
| Success Check | Each die ≤ Target Number = 1 success | die1 + die2 + modifier > target | ❌ Wrong |
| Boons/Threats | Extra dice, keep best 2 | Extra dice + numeric modifier | ❌ Double-counts |
| Natural 20 | Complication (Threat) | No special handling | ❌ Missing |
| Focus Bonus | Die ≤ Discipline = 2 successes | Not implemented | ❌ Missing |
| Momentum | Excess successes (max 1) | Not tracked | ❌ Missing |
| Threat | Complications from nat 20 | Not tracked | ❌ Missing |
| Difficulty | Number of successes needed | Binary success/fail | ❌ Wrong |

**The entire dice rolling mechanic is incorrect.** The current code:
1. Rolls 2d20 and adds them together (like D&D).
2. Compares the sum to a target number (like D&D).
3. Applies a numeric modifier from boons/threats.
4. Has no concept of successes, difficulty, momentum, or threat.

**The official 2d20 system is a "under/over" system where each die is compared individually to the target number, and the count of successful dice is compared to the difficulty.**

## 4. Priority Improvement Plan

### Phase 1: Fix Core Dice Mechanics (Critical)

**What to fix:**
1. Rewrite `DiceService.rollSkillCheck()` to implement the correct 2d20 under/over system.
2. Each die compared individually to target number.
3. Count successes (dice ≤ target).
4. Handle natural 20 as complications.
5. Apply focus bonus (dice ≤ discipline = 2 successes).
6. Compare successes to difficulty.
7. Generate momentum from excess successes (max 1).
8. Remove the numeric modifier from boons/threats.

**New method signature:**
```java
public TaskAttemptResponse rollTaskAttempt(
    int targetNumber,    // attribute + discipline
    int difficulty,      // successes needed
    String focus,        // optional focus name
    int disciplineValue, // for focus bonus calculation
    boolean isShipTask   // character vs ship stats
)
```

**Response should include:**
- List of all dice rolled.
- Number of successes.
- Whether task succeeded.
- Momentum generated (0 or 1).
- Threat generated (from natural 20s).
- Complication description if applicable.

### Phase 2: Add Task Attempt Endpoint (Critical)

**New endpoint:**
```
POST /api/v1/captains-log/tasks/attempt
```

**Request body:**
```json
{
    "characterId": 1,
    "attribute": "FITNESS",
    "discipline": "SECURITY",
    "difficulty": 1,
    "focus": "Hand-to-Hand Combat",
    "isShipTask": false,
    "momentumSpent": 0,
    "threatAccepted": false
}
```

**The endpoint should:**
1. Look up character's attribute and discipline values.
2. Calculate target number = attribute + discipline.
3. Check for applicable focus.
4. Roll 2d20.
5. Count successes with focus bonus.
6. Handle natural 20 complications.
7. Return result with momentum/threat changes.
8. Create a log entry for the task attempt.

## 5. Summary of Findings

| Category | Count | Details |
|----------|-------|---------|
| 🔴 Critical | 3 | Dice mechanics wrong, no task attempts, wrong attribute names |
| 🟠 High | 5 | No momentum/threat, no combat, no probability matrixes, no narrative beats, no lifepath |
| 🟡 Medium | 5 | No character-ship link, ship stats unused, no crew, AI prompts lost, limited prompts |
| 🟢 Low | 4 | No career progression, plain text equipment, no injury system, no campaign tracking |

**The most critical finding:** The entire 2d20 dice system is implemented incorrectly. The current code uses a D&D-style "roll under target" system with numeric modifiers, while the official Captain's Log rules use a "count successes" system where each die is compared individually to the target number. This is not a minor bug — it's a fundamental misunderstanding of the core mechanic that makes every dice roll in the game produce wrong results.

**Second most critical:** The attribute names (Dexterity, Intelligence, Wisdom, Charisma) are D&D-style names, not the Captain's Log names (Fitness, Reason, Insight, Presence). This affects the entire character model and all references to it.

**Third most critical:** There is no momentum or threat system, which are central to the 2d20 gameplay loop. Without these, the game loses its resource management and narrative tension mechanics.

## 6. Recommended Implementation Order

1. **Fix DiceService** — rewrite the core 2d20 mechanic to match official rules.
2. **Rename attributes** — update character model to use correct attribute names.
3. **Add task attempt endpoint** — integrate dice rolling with character stats.
4. **Add momentum/threat pools** — implement the resource tracking system.
5. **Add probability matrixes** — implement the oracle tables from the rulebook.
6. **Add combat system** — implement physical and starship combat.
7. **Add narrative beat structure** — implement the 15-beat three-act mission flow.
8. **Add character-starship relationship** — link characters to their ships.
9. **Add lifepath creation** — implement narrative character generation.
10. **Add crew management** — implement NPC crew members.

This order ensures that the core mechanics are correct before building higher-level features on top of them.
